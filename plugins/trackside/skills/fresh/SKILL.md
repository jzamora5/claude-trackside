---
name: fresh
description: Clear this chat and continue its track (the user may call a track a workspace): save the track, then clear this chat, which reloads the track on its own. Run it when the user types /trackside:fresh, asks in words to clear this chat, or says yes to a question that said plainly this chat would be cleared, such as trackside's own offer. Whenever you suggest it, say in the same sentence that it clears this chat. Starting work "in a fresh chat" or "in a new chat" isn't a request to clear this one. Never on your own.
allowed-tools: Bash(touch "${CLAUDE_PROJECT_DIR}/.trackside/.state/fresh-${CLAUDE_SESSION_ID}")
---
If `${CLAUDE_PROJECT_DIR}` has no `.trackside/` folder, which happens when a chat moves to another folder after it starts, use the nearest folder at or above the current one that has a `.trackside/` wherever this says `${CLAUDE_PROJECT_DIR}`.

1. `cat "${CLAUDE_PROJECT_DIR}/.trackside/.state/track-${CLAUDE_SESSION_ID}" 2>/dev/null` prints the track this chat is bound to, as `<feature>/<track>`. If it prints nothing, or trackside said this chat runs in a worktree, stop here: say that clearing would lose this chat's work, since it can't be saved to a track from here, and that /trackside:save saves a chat that isn't bound.
2. Run the trackside save skill (/trackside:save), without its final reply. It checks first that this chat's work fits its track, and may move the chat to another one.
3. If you have a tool that clears this session, such as clear_session in the Claude desktop app (load it first if it's deferred), call it for this session ("self") and reply only: "Saved. This chat clears when this reply ends; your next message continues <feature>/<track>." Otherwise, as in VS Code or the terminal, where /clear would leave this chat in the list beside a new one with the same name, have the user compact it instead, which keeps one chat: run `touch "${CLAUDE_PROJECT_DIR}/.trackside/.state/fresh-${CLAUDE_SESSION_ID}"`, then reply only: "Saved. To clear this chat, type: `/compact Keep only the current task; the track's files hold the rest.` It stays one chat and continues <feature>/<track> from its next step." Use the full name of the track the chat is on after the save.
